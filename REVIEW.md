# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Grace period logic strictly requires > 10m. Starter converts `(punch_in - start).total_seconds() / 60` to `int` before checking `> 10`, causing 09:40:01 (10m 1s) to floor to 10 and return 0 instead of 10. Also ignores overnight shifts and attendance date context. | Punch-in at 09:40:01 for a 09:30 shift returned `0` instead of `10`. | Calculated exact `total_seconds() > 600`. When true, computed `int(total_seconds // 60)` from shift start. |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python built-in `round()`, which applies banker's rounding (round-to-even) rather than half-up rounding (R4). | Durations ending in `.005` round down to even rather than up. | Implemented `round_half_up` using `decimal.Decimal` and `ROUND_HALF_UP` to 2 decimal places. |
| 3 | `compute_overtime` (lines 44–47) | Does not enforce the R3 30-minute threshold (`>= 30`). Also fails for overnight shifts where `shift_end` is on the next calendar day. | Punch-out 15 minutes after shift end returned `15` instead of `0`. | Checked if difference `>= 1800` seconds; added +1 calendar day to `shift_end` for overnight shifts. |
| 4 | `health` (lines 72–74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity (contract requires 503 if DB is unreachable). | App returns 200 even when MongoDB is offline. | Pings MongoDB via `client.admin.command("ping")`; returns 503 on failure. |
| 5 | `create_employee` (lines 77–85) | Check-then-insert race condition (`find_one` then `insert_one`). Also lacks validation for `shift_start == shift_end` (422), uses naive local datetime for `created_at`, and fails to return epoch milliseconds. | Concurrent identical requests created duplicates; invalid shift times accepted. | Added unique index on `emp_code`, caught `DuplicateKeyError` to return 409, validated `shift_start != shift_end`, and serialized `created_at` as epoch ms. |
| 6 | `list_employees` (lines 88–96) | Offset bug `skip = page * page_size` skips the first page entirely. `total = count_documents({})` ignores the `department` filter. Missing sort by `emp_code` ascending. | Requesting `page=1` returned items starting at index 20; filtered total was incorrect. | Changed to `skip = (page - 1) * page_size`, passed query `q` to `count_documents`, and sorted by `emp_code` ascending. |
| 7 | `punch_in` (lines 99–122) | Missing 404 check if employee exists. Leaks internal MongoDB id (`doc["id"] = ...`). Unsafe check-then-insert race condition. Naive timestamp conversion ignoring IST and overnight shifts (R1). | Punching in for non-existent employee succeeded; concurrent requests created duplicates; overnight shift dates recorded on wrong calendar day. | Verified employee existence (404), computed attendance date via R1, enforced unique compound index on `(emp_code, date)`, handled `DuplicateKeyError` (409), and omitted all id fields. |
| 8 | `list_attendance` (lines 124–150) | In-memory sorting and pagination (`list(find())`), causing severe latency and Out-Of-Memory errors on large datasets (100k docs). Leaks internal id. Missing secondary sort by `emp_code` asc. Missing validation for `date_from > date_to` (422). | Slow query performance / memory spike on large collection; unsorted ties; invalid date range returned 200. | Moved sort, skip, and limit directly to MongoDB query engine using indexes; added validation for `date_from > date_to` (422); serialized records without id. |
| 9 | Database Startup (lines 20–24) | No indexes created at application startup as required by the specification. | Explain queries showed `COLLSCAN` across all collections. | Added FastAPI `lifespan` handler to idempotently create required indexes on `employees` and `attendance_logs`. |
| 10 | Timestamps & Types (throughout) | `punched_at` was not validated as epoch milliseconds (`>= 100000000000`), allowing raw seconds or invalid values. Datetimes in responses were not converted to epoch ms. | Passing Unix seconds (`1783312500`) was accepted; API responses contained ISO datetime strings instead of epoch ms. | Enforced Pydantic bounds for epoch milliseconds and serialized all response instants to epoch ms. |

---

### Examined and Decided NOT a Defect

1. **Storing Calendar Dates & Shifts as Strings**: `date` (`YYYY-MM-DD`) and shifts (`HH:MM`) are stored as strings rather than BSON dates. This is intentional per `DATA_MODEL.md` to prevent unintended timezone conversions across day boundaries.
2. **Absence of Record ID on Attendance Records**: Attendance logs do not have an `id` field in the response contract; records are identified by natural key `(emp_code, date)`.
3. **Module-level MongoClient**: Reusing a single `MongoClient` instance at module level is the recommended connection pooling pattern for PyMongo in FastAPI applications.
